# TikTok Shop 商家秒杀复制与连续续排

使用用户已登录的 Google Chrome，在 TikTok Shop 跨境商家中心先检查日期与已建活动，再复制需要续接的商家秒杀。日常检查在活动结束当天提前补建缺失的下一轮；排期为上一场结束日期的次日 00:00 至新开始日期后第 2 天 23:59，按各站当地时间连续三天。

**创建节奏跟着活动结束日走，不是每天创建。** 例如 14 日建立 15–17 日，15、16 日无需再建，17 日再建立 18–20 日，20 日再建立 21–23 日。每次调用都先读当前时间与后台实际状态；只有确实需要接续时才写入，不能把每天经过一天当作新增一场的理由。

## 范围与输入

- 店铺、站点和轮数以当前请求为准。“按刚录制的流程”对应 JOYO-AUDIO 的 TH → SG → MY，每站检查下一轮是否已覆盖，必要时最多补一场。三站分别判断，可以只补其中一站，也可以三站均跳过；全部已排期、实际新增 0 场也是任务完成。其他店铺、站点或更多轮次需来自用户请求。
- 默认采用日常检查：先找本次目标系列的进行中活动及已创建的后续活动；当本场今天结束、下一轮尚未建立时才补建。已有后续排期时核验后报告，不因还能点击“复制”就一直往后加排。
- “已有后续”必须是紧接本场的目标窗口，并核对同系列、商品、渠道、价格及有效状态。只有更晚的一场、已取消活动或未确认创建成功的活动不能证明下一轮已覆盖。例如仅有 18–20 日但缺少 15–17 日属于断档，需报告。
- 用户明确要求提前加排、指定日期或多轮时，按请求从该站目标系列结束时间最晚的一场继续；用户指定活动名称、ID 或具体来源时优先使用指定来源。多个不同商品系列或来源无法区分时，先问清来源。
- 名称沿用复制页面生成的新名称，除非用户指定命名规则。
- 保留来源的商品/变体、秒杀价、展示渠道、商品或变体级别以及其他复制设置。当前请求另有明确修改时以请求为准。
- 用户可以指定起止日期覆盖默认续排；先核对其与默认规则是否一致。不要把录制中的旧日期、活动 ID、商品 ID 或数字元素索引作为固定输入。

## 工具与定位

没有可用的 TikTok Shop 促销专用连接器时，使用 **Computer Use**，通过 `mcp__cua_repl` 选择 Google Chrome 的现有商家中心标签页。先读取该工具返回的文档及实时状态，再进行交互。可用且适配当前已登录会话的专用连接器可优先处理语义操作，界面核验仍可使用 Computer Use。

域名为 `seller.tiktokshopglobalselling.com`。稳定入口是“广告营销 → 促销活动 → 管理你的促销活动”；列表路径为 `/promotion/marketing-tools/management`。复制页通常为 `/promotion/marketing-tools/flash-sale/create`，`duplicateId` 从本次选择的来源活动产生，不拼接旧录制 URL。

通过当前页面的控件名称、表格行、标签和区域定位。复制按钮必须属于选定来源行；不要点击全页第一个“复制”。日期使用“开始时间”“结束时间”，两处同名“选择时间”通过所在开始/结束区域区分。日期/时间选择器中的“确定”只提交当前选择，底部“同意并发布”才提交活动。避免坐标或旧元素 ID 重放。

核验已建活动时，点击列表中的活动名称进入只读“查看详情”，无需先点“复制”或“编辑营销活动”。页面跳转、切换站点和历史记录翻页可能异步加载；等待预期店铺、活动 ID 或该页特有商品出现后再比对，旧内容仍在不代表新页面的数据相同或不同。详情中的“商品件数”与历史记录中的已添加 SKU 数可能不同，不据此误判商品缺失。需要完整核对创建时的商品/优惠价时，可展开“最近变更”中创建记录的“查看全部”，逐页确认真实内容；未成功读到的页面标注未核验，不声称全量一致。

## 每站执行

先调用可用的时间工具读取本次真实当前时刻，记录北京时间日期/时间，再按页面时区确定该站的当地今天。不要沿用上一次执行或录制的日期；接近午夜或执行时间较长时，在写入前刷新时间判断。北京时间与各站当地时间需要分别表达。

开始写入前，确定并记录本次任务每站的当前日期、来源、已建后续排期、是否需要续建、目标起止时间和轮数。恢复同一任务时沿用这份计划及已完成记录，并检查排期是否仍可执行；不因列表出现刚创建的活动就重新推算另一轮。

按每站实际状态作出决定：

| 后台实际情况 | 本次动作 |
|---|---|
| 本场今天 23:59 结束，紧接的下一轮尚未建立 | 复制本场，建立次日 00:00 至第三天 23:59 的一场活动，再回读。 |
| 本场今天结束，紧接的下一轮已有效排期 | 核验并跳过，不再从后续场继续复制另一轮。 |
| 当前连续有效排期已覆盖到未来日期 | 报告覆盖截止日，本次无需新建。 |
| 有未来活动但中间断档、来源不明或结束时刻不符 | 报告具体问题，不以重复创建同日期活动或擅自改时间来处理。 |
| 用户明确要求提前加排、指定日期或多轮 | 按该请求执行，仍先检查目标是否已存在。 |

核验或补建完成后，报告每站建议的**下次续建检查日**：取该系列已核实、连续有效覆盖链的最后结束日期，届时再次检查是否缺下一轮；不要固定按“今天 + 3 天”推算。例如 14 日已确认 15–17 日排好，则下次检查是 17 日，届时缺少后续才建立 18–20 日；15、16 日无需新增。此日期是检查建议，不代表已创建定时任务。

1. **确认店铺、站点和到期情况。** 读取店铺切换器中的国家与店铺名，同时核对页面地区/时区；查看目标系列的进行中和未开始活动，读实际起止时间，不按名称时间或列表第一行判断。日常模式中，本场在该站今天 23:59 结束且缺少下一轮时，选择该场为来源；若后续活动已经建好，核对覆盖与重复情况并报告“已排期，无需重复续建”。若该系列最近的结束日期晚于今天且已有覆盖，不继续加排。提前/多轮请求则选择用户指定来源或该系列结束最晚的一场。记录来源名称、可见 ID、结束日期、商品范围与实际选中的渠道/级别。选项文字存在不代表已选中。切换国家后重新核对店铺，再读该国列表。
2. **计算下一轮。** 从该站来源活动的当地结束日期计算，不从电脑日期、活动名称中的创建时间或另一站活动计算。新开始日 = 来源结束日 + 1 天；新结束日 = 新开始日 + 2 天；固定为 00:00 至 23:59。例如 10 月 15–17 日 → 18–20 日 → 21–23 日。使用日历加法处理跨月、跨年。
   - 以页面标注的时区为准；录制中 TH 为 GMT+7，SG/MY 为 GMT+8。默认是相同的当地时间规则，不是同一绝对时刻。泰国当地 00:00 对应北京时间 01:00。
   - 需要确定性计算时运行 `scripts/next_window.py`，传入当地来源结束日期和本次页面 UTC 偏移。例如：`python3 scripts/next_window.py --source-end-date 2026-10-17 --utc-offset +07:00`。脚本只计算，不写网站。
   - 若算出的排期已无法满足页面当前的开始时间或预热要求，报告冲突并让用户指定调整；不自动跳过历史日期或改为今天。
   - 用户示例：今天 10 月 14 日，本场在 14 日 23:59 结束，可在 14 日下午约 17:00 提前建立 15 日 00:00 至 17 日 23:59 的下一场，不必等本场结束后再创建。“下午约 17:00”是可提前操作的示例，不是固定触发时间。未来定时检查需用户另行明确安排。
   - 若已有排期中断、活动并非 23:59 结束或当天已错过原接续时间，报告实际间隙及页面限制，再按用户指定方案处理；不把“按日期续三天”当作这些例外的自动修复规则。
3. **检查已有目标。** 检查列表是否已有与本轮日期匹配的同系列活动。日期相同并不足以证明它就是所需复制；查看名称、商品范围、渠道和可见价格。确认一致则记录“已存在并核验”，避免重复建立。来源与已有目标不清楚时先消除歧义。
4. **复制并设置四个时间字段。** 点击选定来源行的“复制”，等待继承的商品内容加载。分别设置并确认开始日期、开始时刻、结束日期、结束时刻；即使日期正确也要核对时间，复制页可能默认显示当前时分。核对实际商品/变体、价格、渠道与级别符合来源，保留原值。复制后商品缺失、价格变化或级别被页面默认值替换时先报告差异，不自行重算价格或改动商品范围。
5. **发布。** 当前任务要求建立/续排活动时，核验后点击“同意并发布”；若只要求预览或方案则停在对应范围。处理下述叠加折扣提示，然后读取成功或错误状态。
6. **回读结果。** 返回“管理你的促销活动”，找到新活动行，核对店铺/国家、活动名称、商家秒杀类型、起止日期/时间/时区及状态。未来活动通常应为“未开始”，不能称为已开始生效。必要时进入详情核对商品与价格。成功弹窗和发布点击不能替代列表回读；商品价格核验是否完成单独说明。
7. **继续剩余范围。** 一站完成并记录结果后切换下一站。多轮请求按每站已回读成功的新活动作为下一轮来源继续递推，不改变当前授权的轮数。

## 叠加折扣提示：用户已确认的处理

遇到“检查商品”“总折扣率超过 80%”等高额折扣提示时，读取受影响商品、原价、预计折扣价、折扣率、日期和可见的叠加优惠详情，核对商品属于本次复制范围，且复制来的价格未被意外改变。按用户已确认的规则继续点击提示中的“发布”，**不修改复制来的价格**，也不自动移除商品。

对符合上述条件的高额折扣提示无需再次询问许可。记录出现过的提示及核对结果。平台可能注明分析仅覆盖部分商品；不能将提示列表视为整场活动的完整价格审核。若商品、价格或优惠内容无法读取，核验不能完成，应报告具体缺失；这项偏好不适用于来源不明、意外改价或其他类型错误。

## 失败、重试与交付

- 发布后空白、加载未结束、报错或超时：先回到管理列表核对是否已建立，再决定是否重试。无法确认结果时不再次点击发布或重复复制，报告“发布已点击，结果待核验”。
- 按站点、轮次保留完成状态，恢复时只处理未完成或未核验项。
- 如活动内商品显示“商家下架”等状态，报告具体商品及状态；已有排期仍按实际活动状态判断，不能因此重复创建活动，也不自动上架、下架或移除商品。
- 交付简表：站点/店铺、来源、当地起止时间与时区、已有或新活动名称/ID、列表状态、商品价格核验范围、最终结果及建议下次检查日；另记实际新增场数与相关提示。使用“已创建并排期”“已存在并核验”“待核验”等准确状态，排期已核实不等于所有价格均已核实。
- 技能本身不安排后台定时任务；用户另行要求自动定期续排时再使用对应自动化工具。
