## 用户明确纠正

- 商品标准要选“全部”；与商品表头全选是两步。
- 发现今天还有遗漏，先补今天仍能创建的活动，再接着建明天。不能直接跳过；判断不清楚时询问。
- Chrome 切店必须走左侧营销中心 → 顶部当前店铺 → 国家和店铺 → 店内秒杀。
- 库存 5、限购 2；保留来源商品和价格。本次并未要求把批量折扣设为 5%，不要把旧活动或其他流程的折扣操作混入。

## 实际界面行为

- 复制活动可能打开新标签；核对新标签中的国家、店铺、来源和所选时间再操作。
- 时间选择弹窗先加载日历，随后才显示“14 N个时段”等可用数量。不要在加载未完成时把空列表当作无可用时段。
- 商品表有时不会把复选框暴露给 macOS AX；用当前截图中的表头复选框全选，然后读取“已选择 N 规格”核对。录制时的坐标不得复用。
- Chrome/Safari 的 AX 文本可能异步改变；元素编号失效时重新读取状态。若标签 DOM 通道失败，可使用同一浏览器的原生 Computer Use；不要无限重试失效通道。
- 输入 URL 时如原生 `typeText` 遗漏标点，用 `paste` 输入已观察到的 URL；无需猜测地址或调用隐藏 API。
- 返回列表曾显示旧缓存。刷新后新场次出现，成功提交前后均不要盲目重复确认。
- “全部商品标准”是界面显示证据，不足以证明存在一个持久化的活动类别设置。
