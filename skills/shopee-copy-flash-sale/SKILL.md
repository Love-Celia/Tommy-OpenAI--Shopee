# shopee 秒杀活动续建

使用已登录的 Shopee 卖家中心，复制当前店铺最近一场有效的店内秒杀，把指定日期的全部平台时段排齐。默认先补今天仍可创建的遗漏，再续建明天。用户指定日期、站点、商品或批量参数时，以本次要求为准。

## 输入与店铺范围

- 未指定范围的“全部续建”包括两个浏览器中的四个店铺站点：Safari 的泰国 `multieffect.th`；Chrome 的泰国 `joyoaudio.th`、新加坡 `joyoaudio.sg`、马来西亚 `joyoaudio.my`。
- 用户只要求一个浏览器、店铺或站点时，仅处理该范围。
- 默认活动库存 **5**，购买限制 **2**；来源活动中的商品、各规格价格及折扣金额继续沿用。批量“折扣”输入框留空。
- 日期为动态输入：从当前客户端日期（Asia/Shanghai）确定今天和明天，不能复用录制时的 2026-10-13/14。读取站点的时区及完整开始、结束日期；若运行时站点日期与用户所说“今天”不同且影响范围，先澄清。
- 时段、数量、可用库存、资格与活动状态必须实时读取；历史示例仅用于核对路径，见 [references/verified-workflow.md](references/verified-workflow.md)。

## 浏览器与切店

使用 **Computer Use（`mcp__cua_repl`）** 操作用户已有的 Safari 与 Chrome 登录会话。核对浏览器、页面中的当前店铺和国家后再写入。

Chrome 的切店路径已经实测：

1. 左侧“营销中心”分组 → **营销中心**。
2. 顶部 **当前店铺** 下拉框 → 国家 → 对应店铺。
3. 确认顶部店铺名称已改变，再进入 **店内秒杀**。

秒杀列表顶部的“当前店铺”可能只是显示文本；切换应回到营销中心。Chrome 即使显示越南、菲律宾，也不纳入本技能默认范围。Safari 使用其自己的泰国登录会话。

优先使用当前 AX/DOM 中的按钮、文字与输入框。每轮动作后读取新状态；控件未暴露时以最新截图定位。不要把历史元素编号、标签 ID、坐标或 URL 查询参数作为固定操作脚本。

## 每个站点的日期与遗漏判断

1. 读取活动列表，核对今天及目标日期的已建时段、启用商品数和状态。已有有效活动不重复创建。
2. 找到该站点最近一场含有效商品的活动，记录它的商品范围及来源标识，作为本轮复制来源。点击 **复制**，打开 **选择时间段**。
3. **先检查今天**的可选时段，将今天仍能创建且缺失的场次按开始时间升序补齐；完成今天的检查后才处理明天。
4. 今天没有可选时段时，对照列表区分“已建齐”和“已经过期/不可创建”。已经过期的空活动不能称为补齐；在结果里说明无法补建。
5. 已有活动若显示 0 个启用商品、关闭、商品异常，视为需要核查，不可直接当作完成，也不可另建同时间段的重复活动。根据明确的本次修复要求处理；不清楚如何修复时询问用户，可继续处理其他确定的缺失时段。
6. 明天按照平台时间选择器提供的时段逐一创建，跳过已建且有效的时段。完成目标日后停止，不续排未要求的后天。

跨午夜场次按**开始日期**归属：例如明天 22:00 至后天 01:00 属于明天的最后一场。每天的场次数与时段可能变化，不能固定为泰国 4、新加坡 5、马来西亚 6 场。

## 逐场复制与提交

对每个缺失且可创建的时段执行：

1. 从本轮已核对的最近有效来源点击 **复制**；确定来源有商品，避免复制 0 商品或异常活动。复制若打开新标签，再次核对国家、店铺与来源，之后才能写入。
2. 打开 **选择时间段**，选目标日期的最早未建时段，点击弹窗 **确认**；核对表单完整的开始和结束时间。
3. “商品标准”必须点击 **全部**。这个类别标准控件与下方的商品全选复选框是两个不同控件，分别操作；它不意味着添加店铺全部商品。
4. 等复制来源的商品及规格加载完。保留来源商品和各规格价格；填写批量活动库存与购买限制，默认为 5 和 2，批量折扣栏留空。
5. 点击 **更新全部**，再勾选商品表头的全选复选框，核对 **已选择 N 规格**；点击 **更新选择**，再点击 **开启**。如果页面支持先全选再批量更新，也可采用该顺序，但必须验证参数已应用。
6. 等批量启用完成，核对启用商品数和错误提示。规格数与商品数不同，不能拿两者直接比较。不能为了达到历史数量强行添加商品、改价或改库存；不符合资格或库存不足的规格，说明原因，需要改动时询问用户。
7. 点击页面底部的活动 **确认**，观察成功信息中的确切日期与时段。
8. 返回活动列表，核对新活动的日期、起止时间、启用状态和有效商品数。确认保存后处理下一时段。若改用刚建活动作为最新来源，先确认复制的商品与规格范围没有丢失；不能让暂时未启用的规格在连续复制中静默消失。

## 保存核验与停止条件

- 创建成功弹窗只是中间证据，必须回到列表看到对应活动才算完成。返回列表可能显示缓存；刷新列表后核对，不能因为暂时没看到新行就再次提交。
- 保存过程超时、页面空白或结果不明确时，先查列表是否已经创建；必要时打开对应详情检查，防止重复。
- 对每场保留站点、完整起止时间、来源/新活动 ID（页面可见时）、所选规格数、启用商品数，以及库存和限购应用后的证据。遇到不一致再打开详情核验，不需要对已经确认的相同事实反复检查。
- 目标时段不可选时，先查列表确认是否已有活动，区分已建、已过期和平台限制。无有效来源、缺失时段不可创建、资格校验失败或价格需要改变时，说明具体问题；不静默跳过，不擅自改价。阻塞只影响相关站点或场次，可继续其他已明确的工作。
- 用户要求续建即授权范围内的复制、启用与确认提交；这份技能本身不创建每日定时任务，也不扩大到未请求的日期或店铺。

## 完成反馈

用简短表格按浏览器/店铺/站点报告：今天补建场数、明天已有与新建场数、最终是否排齐，以及无法补建或待用户处理的具体场次。说明新建活动使用的库存、限购与商品价格规则。

保存一张能看清日期和已建活动的结果截图并在回复中展示，保留便于用户检查的最终列表页。仅在全部目标活动都已回读核实后，报告该站点完成。
